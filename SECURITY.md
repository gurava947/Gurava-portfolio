# Security

This application ships in two shapes, and the security story differs between them:

| Shape | What runs | Attack surface |
| --- | --- | --- |
| **Local** (`npm run dev`, `npm start`, `node backend/server.js`) | Express 5 + `node:sqlite` bound to `127.0.0.1` | One read-only catalogue API plus one mutating route, `PATCH /api/settings` |
| **Published** (Vercel) | Static bundle only | `vercel.json` rewrites every path to `/index.html`, so `GET /api/settings` answers HTML and `PATCH /api/settings` is refused with `405` by the static host — there is no API process, no database and no credential in the deployment |

The threat model for the local shape is a browser page on another site, or another machine on the network, trying to *write* to a server the owner uses; the published shape has no write surface at all.

## The twenty checkpoints

| # | Checkpoint | Status | Where it lives |
| --- | --- | --- | --- |
| 1 | Hide API keys | **No key exists to hide.** The app calls no third-party API, and the scanner fails the build if one ever appears. | `scripts/audit-security.mjs`, CI `Security audit` step |
| 2 | Check environment variables | `API_PORT`, `FRONTEND_PORT`, `HOST`, `PORT`, `API_WRITE_TOKEN` and `DATABASE_PATH` are the only variables the server reads; each is documented in the template with the default it falls back to, and no secret is required to run. Values live in `.env`, which is gitignored. The three `AUDIT_*` names belong to `scripts/audit-security.mjs` and only ever loosen a local check run. | [`.env.example`](.env.example), [backend/server.js](backend/server.js), [backend/db/connection.js](backend/db/connection.js) |
| 3 | Protect admin routes | The only privileged route is `PATCH /api/settings`; it sits behind the write guard, and the body parser runs after the guard so a refused write is never buffered. Unknown `/api/*` methods end in a 404, not the app shell. | [backend/middleware/writeGuard.js](backend/middleware/writeGuard.js), [backend/app.js](backend/app.js) |
| 4 | Add authentication | `API_WRITE_TOKEN` turns writes into a bearer-authenticated operation, compared as SHA-256 digests with `timingSafeEqual` so neither the length nor a prefix leaks through timing. There are no user accounts to log into — see #17. | [backend/middleware/writeGuard.js](backend/middleware/writeGuard.js) |
| 5 | Check user access | Single-owner model: reads are public catalogue data, writes are gated by bind address, token and origin. When the server is bound to an interface other machines can reach (`HOST=0.0.0.0`, a LAN address) writes are refused for the browser, because a token the page holds is not a secret. | [backend/middleware/writeGuard.js](backend/middleware/writeGuard.js), [backend/server.js](backend/server.js) |
| 6 | Sanitize forms | The studio form posts JSON that `validateSettingsPatch` checks against a whitelist before anything reaches SQL: unknown groups and unknown keys are rejected with 400, numbers must fall inside a declared range, enums and booleans are type-checked, colours must match `#rrggbb`, and a WCAG contrast guard refuses unreadable pairings. Bodies are capped at 32 kB with `strict` JSON parsing, so trailing text is rejected. | [backend/validators/settings.js](backend/validators/settings.js), [backend/services/settingsService.js](backend/services/settingsService.js), [backend/app.js](backend/app.js) |
| 7 | Protect against XSS | React escapes rendered text; no application code under `src` uses `dangerouslySetInnerHTML` or writes `innerHTML` (the only hits are test assertions reading rendered markup). CSP allows `'self'` scripts only (no `unsafe-eval`, no `unsafe-inline`) and pins `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'self'`, `form-action 'self'`. | [backend/app.js](backend/app.js), [vercel.json](vercel.json), tests in [backend/tests/api-security.test.js](backend/tests/api-security.test.js) |
| 8 | Add rate limits | In-memory fixed-window budget per client socket address: 600 reads and 120 writes per minute, `429` with `Retry-After`, bounded store that clears instead of growing. `trust proxy` is off, so `X-Forwarded-For` cannot mint a fresh bucket. | [backend/middleware/rateLimit.js](backend/middleware/rateLimit.js) |
| 9 | Secure API endpoints | No banner, nosniff, bounded client errors, generic 500 text with the real error logged server-side only, explicit `code` for 401/403/413/429, and a 404 handler for unknown API paths. | [backend/middleware/errorHandler.js](backend/middleware/errorHandler.js), [backend/controllers/apiController.js](backend/controllers/apiController.js) |
| 10 | Check CORS settings | No `Access-Control-Allow-Origin` is emitted by the local server or by `vercel.json`: cross-origin reads are not offered. The gap that "no CORS" leaves — a foreign page still being able to *send* a write — is closed by the same-origin `Origin` check in the write guard. | [backend/middleware/writeGuard.js](backend/middleware/writeGuard.js), [vercel.json](vercel.json) |
| 11 | Add security headers | `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Cross-Origin-Resource-Policy`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`, `Strict-Transport-Security` and CSP on every response, identical in both shapes. | [backend/app.js](backend/app.js), [vercel.json](vercel.json) |
| 12 | Turn off debug mode | `x-powered-by` disabled, no `console.log`/`debug`/`info` call in the application code (the ten remaining `console.error`/`console.warn` sites in `src` each report a real failure the owner can act on), source maps off (the build emits none), and the error handler answers a fixed sentence for 5xx. | [backend/app.js](backend/app.js), [backend/middleware/errorHandler.js](backend/middleware/errorHandler.js) |
| 13 | Update dependencies | In-range updates applied on this pass (lockfile-resolved; the `package.json` ranges stay caret floors): `express 5.2.1 → 5.3.0`, `react`/`react-dom 19.3.0 → 19.3.1`, `postcss 8.5.28 → 8.5.32`. `npm audit` reports 0 vulnerabilities; the CI gate blocks high/critical and, unless opted out, any advisory. | [`package.json`](package.json), `scripts/audit-security.mjs` |
| 14 | Remove unused packages | `@testing-library/user-event` deleted — nothing imported it. The three Testing Library packages moved from `dependencies` to `devDependencies`, where they belong; `@testing-library/dom` stays because `@testing-library/react` 16 requires it as a peer. | [`package.json`](package.json) |
| 15 | Check exposed files | `.gitignore` keeps SQLite files, logs, `dist/`, `.vercel/` and `.env*` out of the repository; the audit rejects any of them being tracked (`.env.example` is the deliberate exception) and warns about a local `.env` the ignore rules do not cover. Static serving reads `dist/` only, and the bundle contains no maps, databases or environment files. | [`.gitignore`](.gitignore), `scripts/audit-security.mjs`, [backend/app.js](backend/app.js) |
| 16 | Secure the database | `node:sqlite` with foreign keys enforced, WAL journaling and a busy timeout. Every value is a bound parameter, and the only identifiers interpolated into SQL — table and column names — come from a static `TABLES` allowlist that the validator has already intersected the request with, so no input reaches the statement text. Multi-table writes run inside `BEGIN IMMEDIATE` … `COMMIT` with `ROLLBACK` on failure. The file itself never leaves the machine and is never published. | [backend/db/connection.js](backend/db/connection.js), [backend/repositories/settingsRepository.js](backend/repositories/settingsRepository.js#L104), [backend/db/migrate.js](backend/db/migrate.js) |
| 17 | Hash passwords | **No subject: there are no accounts, so no password is stored or compared.** The one credential the server does accept (`API_WRITE_TOKEN`) is never stored or logged; it is digested with SHA-256 and compared in constant time. | [backend/middleware/writeGuard.js](backend/middleware/writeGuard.js) |
| 18 | Check git for secrets | The audit sweeps the working tree *and* `git rev-list --all` with `git grep` for private-key blocks, cloud and AI provider tokens, Slack/GitHub/npm credentials, JWTs, secrets carried in URLs, and long literal values assigned to `*secret*`/`*key*`/`*token*` names. Values are masked in the report. Files `.gitignore` already holds back are not scanned — they can never reach a commit — but the count is printed, so a credential sitting on the machine is still visible in the report. | `scripts/audit-security.mjs` |
| 19 | Run a security audit | `npm run audit:security` runs the dependency audit, the credential sweeps and the exposed-file checks, exits non-zero with a report, and is a step in CI before the test and Lighthouse jobs are allowed to matter. | [`package.json`](package.json), [`.github/workflows/lighthouse.yml`](.github/workflows/lighthouse.yml) |
| 20 | Protect the published deployment | The Vercel target serves static files with the same header set as the local server and no API, no database and no environment secrets. `npm run build:vercel` also strips the settings-sync code path (`import.meta.env.MODE === "vercel"`), so the published bundle issues no write request at all. | [vercel.json](vercel.json), [src/hooks/useTheme.js](src/hooks/useTheme.js:349), [VERCEL_DEPLOY.md](VERCEL_DEPLOY.md) |

## Verify it yourself

```bash
npm run audit:security   # advisories + credential + exposed-file sweep (offline: AUDIT_SKIP_DEPENDENCIES=1)
npm test                 # 310 frontend tests, then 23 backend tests including api-security.test.js
npm run build && node backend/server.js
curl -sD - -o /dev/null http://127.0.0.1:3000/api/health   # headers
curl -s -X PATCH http://127.0.0.1:3000/api/settings -H 'Origin: https://evil.example' -H 'Content-Type: application/json' -d '{}'
```

## Trade-offs worth knowing

- **`script-src` and `connect-src` have no third-party origin at all.** The Python playground's Pyodide runtime is committed as a ~16 MB same-origin bundle under [public/playground/pyodide](public/playground/pyodide), and the worker loads it from that path, so the CDN fallback that used to retry from a jsDelivr `indexURL` was dead code on every deploy. It is gone ([public/playground/python.worker.js](public/playground/python.worker.js)), and with it the only remote source of executable code. The cost is that a build which somehow ships without those assets shows a run error instead of silently pulling Python in from the internet. `api-security.test.js` pins both directives, and a second test pins the whole policy against the copy in `vercel.json`.
- **Preview iframes are same-origin, not sandboxed.** [src/components/ProjectWorkspace.jsx](src/components/ProjectWorkspace.jsx) measures the rendered page through `contentDocument`, which `sandbox` would forbid. The embedded code is the owner's own catalogue, served from the same origin as the data it reads, so sandboxing buys nothing against a real adversary while breaking device-frame sizing. External embeds (the two YouTube players) send `referrerPolicy="no-referrer"` and load lazily; those attributes are set in `catalog/source/components/static/`, because `src/projects/` is copied from there by the catalog build and editing the copy does not survive a rebuild.
- **The write guard accepts `X-Forwarded-Host` as well as `Host`.** Vite proxies `/api` to a different port and tunnels rewrite the host header, so a strict `Host` comparison would reject the owner's own browser. `Origin` is written by the browser and cannot be forged from another page, so the cross-site write the check exists to stop still fails.
- **Exposing the local server to the network is read-only by design.** `HOST=0.0.0.0` makes `PATCH /api/settings` answer `403 WRITE_LOCKED`; that is the intended behaviour, not a regression to work around.
